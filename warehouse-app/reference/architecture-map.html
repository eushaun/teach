The Architecture Map

Four layers, one primitive, and where every page's number comes from. Print-friendly: keep it beside the code. Badges show how often a maintainer touches a path: hot = most changes land here · warm = touched per feature or per incident · cold = plumbing, rarely edited. Line numbers are from the local checkout (main @ 135eac9); production runs origin/main @ 0b134ca, two commits ahead.

2 The engine, as one picture

Every cover figure, order quantity and urgency band follows one recipe: opening stock → projection.project over periods from a DemandSeries, with arrivals from inbound grading → take a reading.

 daily_sales ─────────────────────────────► demand.channel_demand ──┐
 daily_soh ─► monthly_warehouse_velocity ─► demand.warehouse_demand ┤
                                                                    ▼
                         demand.location_demand (picks basis per location from market_config)
                                                                    │ DemandSeries
 POs / TOs / JAS ledger / Amazon counters / FBA shipments           │
        ─► inbound_grading ─► arrivals (weighted, dated)            │
                                                                    ▼
 opening SOH (inventory_levels.quantityavailable, Amazon overlay) ─► projection.project(...)
                                                                    ▼
   readings: weeks_of_cover(cap 52) · deficit_against(floor, from_period=transit)
             · min_point · gap_before · first_stockout
                                                                    ▼
   cover on Dashboard / All SKUs / Alerts / Overstock / Velocity
   quantities on Transfers / Replenishment / Factory Buy

"Policy goes in the inputs (periods, arrivals, floor), never in a forked loop." — the design rule from PROJECTION-ALIGNMENT-PLAN.md.

Steps 6–8 log and continue on error; every other step aborts the run. The response cache is invalidated only after the last step succeeds. Every source is a cross-repo contract with ltd-dbx-asset-bundle.

6 The maintainer's three rules

1 · No tests: the harness is the gate, and main is production. Run compare_projections dump before and after any engine change; a push to main deploys in about four minutes.

2 · Every service defaults market="US". Pass market=market on every call, or AU silently returns empty or US-shaped data.

3 · The response cache has no TTL. Bump CALC_BASIS_VERSION with any rule change; out-of-band DB edits stay invisible until a sync, admin save or restart.

7 Newcomer reading order

  1. CLAUDE.md (in chunks) — the authoritative map, gotchas and release checklist.
  2. backend/app/services/market_config.py — every warehouse, route and ID; the vocabulary everything else uses.
  3. PROJECTION-ALIGNMENT-PLAN.md ("Why", "Target", "Decisions from the business") — why the code is shaped around one primitive.
  4. backend/app/services/projection.py — the ~300-line core; every number is a reading of project().
  5. backend/app/services/demand.py — demand bases and the seasonal forecast (constants at the top).
  6. backend/app/services/inbound_grading.py — what incoming stock counts, and when it lands.
  7. backend/app/services/warehouse_velocity.py (get_batch_seasonal_woc, _cover_for) — how the cover figure on every page is produced.
  8. backend/app/services/fba_replenishment.py — the highest-stakes engine (weekly Amazon orders).
  9. backend/app/services/transfers.py + case_packs.py — the second quantity engine.
  10. backend/app/services/databricks_sync.py (orchestrators at the bottom first) — where data comes from and how a sync fails.
  11. backend/app/routers/dashboard.py (/stock-cover, /fba-replenishment) + services/cache.py — the endpoint pattern and caching.
  12. backend/app/middleware/auth.py + frontend/src/api/client.ts — auth and market plumbing on both sides.
  13. frontend/src/App.tsx, components/Layout.tsx — routes, guards, nav, CHANGELOG.
  14. frontend/src/pages/ReplenishmentOrder.tsx (skim) — the page planners live in; frontend patterns at scale.
  15. backend/app/tools/compare_projections.py — the regression gate you must run.
