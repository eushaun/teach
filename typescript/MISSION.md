# Mission

> **Reach comfortable fluency in TypeScript — able to read, write, and reason about idiomatic TypeScript with the same confidence I have in Python.**

## Why

- **MCP servers**: The Model Context Protocol's primary SDK is TypeScript. Being able to build and modify MCP servers is a concrete, near-term payoff.
- **LLM-assisted ("vibe") coding**: AI coding tools generate a lot of TypeScript. Fluency means being able to *judge, debug, and steer* generated code instead of trusting it blindly.
- **The web-app direction**: The broader ecosystem (web apps, tooling, SDKs) is leaning TypeScript. This is ecosystem literacy.
- **Career broadening**: A serious second language alongside Python/SQL makes a more versatile engineer.

## Learner profile

- **Day job**: Data engineering (Airbyte, Databricks, Power BI stack)
- **Strong**: Python, SQL
- **None**: JavaScript — TypeScript is being learned *as* the language, with JavaScript runtime concepts taught inline as needed
- **Session budget**: ~30 minutes per session

## Definition of done

"Comfortable fluency" means:

1. Can read an unfamiliar TypeScript codebase (e.g. an MCP server) and follow what it does
2. Can write a small, idiomatic TypeScript program from scratch — types, functions, async, modules
3. Can understand and fix compiler errors without panic
4. Can review LLM-generated TypeScript and spot what's wrong or unidiomatic

## North-star milestone

Build a small working **MCP server in TypeScript** using the official SDK. Not the end of the journey, but the proof-of-fluency checkpoint that ties directly to the mission.
