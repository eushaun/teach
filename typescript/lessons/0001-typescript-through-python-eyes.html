TypeScript · Lesson 1 · ~30 minutes

TypeScript Through Python Eyes

You'll run real TypeScript in your browser, translate three pieces of Python syntax, and watch the compiler catch a bug that Python would have let through to production.

Why this matters for your mission: the official MCP SDK, most LLM-generated app code, and the modern web stack are all TypeScript. Fluency starts with one mental model and a handful of syntax remaps — and you already own most of the underlying concepts from Python.

1 · The one big idea

You've seen Python type hints:

def label_table(table: str, row_count: int) -> str:
    return f"{table}: {row_count} rows"

Python ignores these at runtime. They're documentation unless you separately run a checker like mypy — and even then, the code runs anyway.

TypeScript looks remarkably similar:

function labelTable(table: string, rowCount: number): string {
  return `${table}: ${rowCount} rows`;
}
The big idea: TypeScript types are enforced, then erased. The compiler refuses to build code with type errors — it's a mandatory mypy. Then it strips every annotation and emits plain JavaScript, which is what actually runs. Types exist only at compile time; the running program has never heard of them.

Source: TypeScript for the New Programmer — "TypeScript's type system was designed to be erased".

One more piece of the picture: TypeScript never runs directly. It compiles to JavaScript, which runs in browsers or in Node.js (the JS equivalent of the python command). You don't need to install anything today — we'll use the official in-browser Playground.

2 · Three syntax remaps

Remap 1 — variables: const and let

PythonTypeScript
table_name = "fact_orders"
batch_size = 500
batch_size = 1000  # fine
 
const tableName = "fact_orders";
let batchSize = 500;
batchSize = 1000;  // fine — it's let

Python has one way to bind a name. TypeScript makes you choose: const (can never be reassigned) or let (can be). Idiom: default to const; use let only when reassignment is the point. Also note: camelCase instead of snake_case, and semicolons at the end of statements.

Remap 2 — the primitive types

For a data engineer, number is the surprise: there is no int/float split — every number is a 64-bit float. (Where Python has None, TypeScript has two nothing-values, null and undefined — parked for a future lesson.) Source: Everyday Types, the official handbook.

Remap 3 — functions

PythonTypeScript
def is_large(row_count: int) -> bool:
    return row_count > 1_000_000
 
function isLarge(rowCount: number): boolean {
  return rowCount > 1_000_000;
}

Three mechanical changes: def → function, the -> arrow becomes : after the parentheses, and the body lives in braces instead of an indented block. Parameter annotations are written identically. Even the 1_000_000 digit separator carries over. And print(...)? That's console.log(...).

One genuinely new thing — type inference. TypeScript works out unannotated types from values:

const tableName = "fact_orders";  // inferred: string
let batchSize = 500;              // inferred: number
batchSize = "big";                // ❌ Type 'string' is not assignable to type 'number'

Idiomatic TypeScript annotates function parameters and return types, and lets inference handle local variables.

3 · Hands on — make the compiler work for you

Open the TypeScript Playground in a new tab. It's the official in-browser editor: red squiggles are the compiler talking to you, and the Run button executes the compiled JavaScript (output appears in the Logs tab on the right).

1

Run your first TypeScript. Delete whatever is in the editor and paste:

function labelTable(table: string, rowCount: number): string {
  return `${table}: ${rowCount} rows`;
}

const message = labelTable("fact_orders", 1250);
console.log(message);

Press Run. You should see fact_orders: 1250 rows in the Logs.

2

Break it on purpose. Change 1250 to "1250" (a string). Don't run it — just watch. A red squiggle appears immediately. Hover over it and read the message:

Argument of type 'string' is not assignable to parameter of type 'number'.

Read TypeScript errors backwards: what was expected (number), what was given (string). In Python this bug ships and explodes at 2am in a pipeline; here it never compiles. Fix it back to 1250.

3

Feel the difference between const and let. Below console.log(message), add:

message = "something else";

Read the new error. Now change const message to let message — the error vanishes. Change it back to const and delete the reassignment line: the value never needed to change.

4

Write a function from scratch (no peeking at Remap 3): a function isLarge that takes a row count (number) and returns whether it exceeds one million (boolean). Then check yourself:

console.log(isLarge(2_500_000));  // should print: true
console.log(isLarge(800));        // should print: false

If the squiggles disagree with you, hover and read — that's the feedback loop that will teach you this language.

5

See inference. Hover your mouse over message in the line where it's declared. The tooltip shows const message: string — you never wrote that type. The compiler inferred it. Hovering to ask "what type does the compiler think this is?" is a core TypeScript skill.

Your win today: you wrote and ran real TypeScript, and you made the compiler catch a type bug before the code ran — the single thing Python type hints never did for you.
