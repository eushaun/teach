Python → TypeScript

A growing translation table for a Python speaker. Updated as lessons progress.

The one big difference: Python type hints are advisory — the interpreter ignores them. TypeScript types are enforced — code with type errors won't compile. Then the types are erased: the JavaScript that runs contains no types at all.

String interpolation

PythonTypeScript
f"Loaded {n} rows"
 
`Loaded ${n} rows`

Backtick strings are called template literals. Note the $ before the braces.

Functions

PythonTypeScript
def label_rows(
    table: str,
    count: int,
) -> str:
    return f"{table}: {count} rows"
 
function labelRows(
  table: string,
  count: number,
): string {
  return `${table}: ${count} rows`;
}
  • def name(...) -> T: becomes function name(...): T { }
  • Braces { } replace the colon + indentation. Indentation is convention only — the braces are what count.
  • Parameter annotations look identical: name: type.
  • Unlike Python hints, these annotations are checked: calling labelRows(42, "users") is a compile error.

Loops

PythonTypeScript

    print(t)
 
for (const t of tables) {
  console.log(t);
}
Trap: for...in exists but iterates indices ("0", "1", "2"), not values. Values = of.

Records (objects & type aliases)

PythonTypeScript
class TableSync(TypedDict):
    table: str
    rows_loaded: int
    error: NotRequired[str]

sync: TableSync = {
    "table": "fact_orders",
    "rows_loaded": 120_000,
}
print(sync["table"])
 
type TableSync = {
  table: string;
  rowsLoaded: number;
  error?: string;
};

const sync: TableSync = {
  table: "fact_orders",
  rowsLoaded: 120_000,
};
console.log(sync.table);
  • Objects = TypedDict, not dict: fixed known fields, dot access, typo-checked. Arbitrary-key dicts (Record/Map) come later.
  • Keys unquoted in literals; access with sync.table.
  • In type definitions: members end with ;. In data literals: commas.
  • field?: T = optional (≈ NotRequired). Reading it gives T | undefined.
  • TableSync[] = an array of records — a typed result set.
  • interface in the wild ≈ same job as type for object shapes.

Type inference

const tableName = "fact_orders";   // TS knows: string
let batchSize = 500;               // TS knows: number
batchSize = "big";                 // ❌ compile error

You rarely annotate local variables — TypeScript infers their types from the value. Annotate function parameters and return types; let inference handle the rest.
