The PBIP File Map

Every file in a project, what it is, and how much attention it deserves in an agent's PR. Print-friendly — keep it beside the diff. Badges: read = read every changed line · glance = confirm it's the change you expected · noise = churn/plumbing, skip unless surprising.

Top level — reports/<Workspace>/<Project>/

File / folderWhat it isIn a diff
<name>.pbip Tiny JSON pointer to the report folder. Open this to open the project in Desktop. noise
<name>.SemanticModel\ The model item — tables, partitions (M), relationships, measures. glossary read
<name>.Report\ The report item — pages, visuals, bookmarks, theme. glossary read
.gitignore Excludes .pbi\cache.abf + localSettings.json. Desktop creates it once. glance

*.SemanticModel\ — the model, in TMDL

File / folderWhat it isIn a diff
definition\ The whole model as TMDL. This folder is the model. read
definition\tables\<Table>.tmdl One file per table: columns, partition M, measures, hierarchies, annotations. Measures live in whichever table hosts them (ours: Measures - * tables). read
definition\relationships.tmdl All relationships: endpoints, cardinality, direction, active flag. read
definition\model.tmdl Model-level properties, shared expressions (parameters), ref ordering of tables/roles/cultures, annotations. glance
definition\database.tmdl Compatibility level. Rarely changes. glance
definition\cultures\*.tmdl Linguistic metadata (Q&A schema). Desktop-generated churn magnet. noise
definition\roles\*.tmdl RLS roles + DAX filters (when present). read
definition.pbism Core settings + format version (4.0+ ⇒ TMDL allowed). glossary glance
.platform Fabric git identity: type, display name, logicalId. Display names are load-bearing for deploys; duplicate logicalIds hard-fail. read
diagramLayout.json Model-view diagram positions. Cosmetic. noise
.pbi\ (cache.abf, localSettings.json) Machine-local cache/settings — gitignored; must never appear in a PR. noise

Whole project pbip:pbip (structure/renames/forks) · pbip:pbip-validator agent · deploy/validate.py (the CI gate) · fabric-cicd via deploy/deploy.py · fabric-cli:fabric-cli (service side) Validation reads everything; merge to main deploys changed projects to prod.

Diff triage — the 60-second version

  • Which folder? .SemanticModel = logic/data changed; .Report = presentation/binding changed. A PR that was "move a card" should not touch the model — and vice versa.
  • In TMDL: lines after = are DAX/M — read them like code. lineageTag/ref reshuffles are churn. Partition source = changes mean the data feed changed → needs a refresh + closest look.
  • In visual.json: position moved it, query re-bound it, objects re-styled it, filterConfig re-filtered it.
  • Red flags anywhere: .platform display-name changes (deploy duplicates!), .pbi\ files in the diff, a thin report growing a .SemanticModel, whitespace-only churn across many files (line-ending normalization — forbidden by * -text).
