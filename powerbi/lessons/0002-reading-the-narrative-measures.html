Reading the Narrative Measures

How "This period at a glance" assembles prose from guarded DAX — and how to spot, in a diff, the one change that silently kills it.

Why this lesson (your mission)

The EMEA dashboard's narrative panel is a system an agent built and will touch again: measures in Measures - Narrative.tmdl feeding a textbox in narrativePanel/visual.json. It has already broken once in review — a Desktop save froze the text — and the only place that bug was visible was the diff. This lesson makes both files readable so the next PR can't sneak that past you.

Your win for today: given the narrative TMDL or a diff to the narrative textbox, you can say (a) what will render for a given filter state, (b) why a line or clause disappeared, and (c) whether a diff is churn, a meaning change, or a broken binding.

1 · The idea: prose is just another measure

There is no AI at runtime. Each line of the panel is a text measure that formats numbers you already trust — the same guarded measures behind the KPI tiles — into a sentence. Because it's a measure, it re-evaluates with every slicer change, for free. The whole system is four public measures ([Narrative Headline], [Narrative Channel], [Narrative Mix], [Narrative Units]) plus hidden _narr* helpers, all in one TMDL file:

reports/EMEA/EMEA Performance Dashboard/
  EMEA Performance Dashboard.SemanticModel/definition/tables/Measures - Narrative.tmdl

2 · The clause pipeline (the core idiom)

Every sentence is built in three steps. Read them once and the whole file opens up:

StepWhat it looks likeJob
Guarded ingredient [Sales vs Budget %] Returns BLANK() unless the base is > 0 — the model-wide rule that a % against a non-positive base must never exist.
Clause VAR _cBudget = IF(ISBLANK(_p), "", "down " & FORMAT(ABS(_p),"0.0%") & " vs budget") Wraps one ingredient in words. Blank in → empty string out. A clause never invents a number.
Assembly CONCATENATEX(FILTER(…), [@txt], ", ", [@ord], ASC) Joins only the non-empty clauses, in a fixed order, with separators.

The assembly step is the part worth memorising — it's DAX's version of ", ".join(x for x in parts if x):

VAR _compare =
    CONCATENATEX(
        FILTER(
            UNION(
                ROW("@ord", 1, "@txt", _cLW),
                ROW("@ord", 2, "@txt", _cBudget),
                ROW("@ord", 3, "@txt", _cLY)
            ),
            [@txt] <> ""                -- drop empty clauses
        ),
        [@txt], ", ", [@ord], ASC        -- join survivors, in order
    )

Three things to notice as a reviewer: the UNION-of-ROWs is just an inline table of candidate clauses1; the FILTER is why a blank budget produces a shorter sentence instead of "0.0% vs budget"; and the explicit [@ord] sort means clause order is deliberate — a diff that reorders those ROWs changes the sentence, not just the code layout.

3 · The gates: why a whole line disappears

Clauses guard fragments; gates guard lines or the whole panel. They're plain IFs at the top or bottom of each measure:

Gate (in the TMDL)Effect when it fires
NOT [_narrOneCurrency] → BLANK()
(_narrOneCurrency = HASONEVALUE('Market'[Currency]))		 Whole panel blanks. A cleared Market slicer would otherwise add £ + € + $ and present the sum as money. Blank beats a wrong number.
HASONEVALUE('Channel'[channel]) The channel line vanishes — "Amazon was the largest channel" is meaningless when Amazon is the only channel in scope.
Redundancy guard (top channel ≥ 99.5% of revenue, nothing else behind budget) Channel line vanishes — it would restate the headline word for word.
FY-grain check in the headline Shows one "vs LFY" clause — at FY grain, prior period and last year are the same year; two identical numbers would print without this.

Review rule of thumb: when a line is missing on the canvas, the explanation is a gate, and the gate is in the TMDL. Nothing about visibility lives in the report JSON.

4 · The rendering contract — and the one diff that kills it

The panel is a textbox whose paragraphs use dynamic values: each paragraph's textRun binds a measure instead of holding a string2. Healthy binding, in …/pages/Overview/visuals/narrativePanel/visual.json:

"textRuns": [ {
  "value": { "expr": { "Measure": {
      "Expression": { "SourceRef": { "Entity": "Measures - Narrative" } },
      "Property": "Narrative Headline" } } },
  "textStyle": { … } } ]

Now the failure you already met once. If anyone opens that textbox's text editor in Desktop, the save flattens every binding into whatever string was on screen:

"textRuns": [ {
  "value": "📉 UK, Week 12: revenue £120,000, £30,000 below budget (20.0%) — …",
  "textStyle": { … } } ]

The panel still looks perfect in that filter state — it just never updates again. On the canvas this is invisible. In the diff it's unmistakable: "value" changes from an object with expr to a plain string. That is the single highest-value pattern to burn in from this lesson.

5 · Prove it to yourself

Predict the render. Filter state: UK, a completed week. [Sales] = £120,000, [Sales PP] = £125,000, [Budget] is BLANK() (no budget row loaded for that week), [Sales LY] = £100,000. What does the headline line render?

The blank budget flows: guarded ingredient returns BLANK → the budget clause becomes "" → FILTER drops it → CONCATENATEX joins the two survivors. The sentence gets shorter; nothing errors, nothing prints a fake number. (The whole line only blanks when [Sales] itself is blank or a panel-level gate fires.)

Triage the diff. Four hunks from a hypothetical PR touching the dashboard — classify each as you would in review:

6 · Where this shows up next

The same three-step idiom (guarded ingredient → clause → filtered CONCATENATEX) is how you'd read any future agent-built text: dynamic titles, alert strings in the weekly Slack summary, tooltip sentences. And the binding-freeze diff pattern applies to every textbox with dynamic values, not just this panel.
